# Tooner Development Plan

> 4-phase, 22-week roadmap. Vision: Tooner is a thin UI shell over MarkItDownJS — zero processing logic of its own.

---

## Cross-Cutting Decisions

### State Management: Add Zustand in Phase 1

Current `App.jsx` has 6 `useState` calls forming an ad-hoc state machine. Phase 3 (batch processing, model selector, chunk inspector) will make this unmanageable. Add Zustand (~1.2KB gzipped) early.

**Store structure:**
- `src/store/useAppStore.js` — state machine (state, file, progress, results, error, batch state)
- `src/store/useSettingsStore.js` — model selection, chunk config, UI prefs (Phase 3)

**Migration:** Mirror existing useState fields exactly → replace useState in App.jsx → components read from store directly.

### MarkItDownJS Dependency: Already Primary

MarkItDownJS is already P0 in the registry. Phase 2 is purely **subtraction** (deleting fallback converters), not introducing new dependencies. Key timing note: `@markitdownjs/optimizer`, `@markitdownjs/pack`, and model-aware tokenizers in `@markitdownjs/chunking` may not ship by Phase 2. Plan has fallback approaches for each.

### Test Coverage

Current: 6 test files in `src/converters/__tests__/` (converter-focused only). No component, tokenizer, or integration tests.

## Phase 2: MarkItDownJS Migration (Weeks 5-10)

**Goal:** Delete 6 fallback converters, simplify tokenizer.js from 701 → ~300 lines.

| File | Action |
|------|--------|
| `src/converters/PdfConverter.js` | **Delete** |
| `src/converters/DocxConverter.js` | **Delete** |
| `src/converters/ExcelConverter.js` | **Delete** |
| `src/converters/CsvConverter.js` | **Delete** |
| `src/converters/JsonConverter.js` | **Delete** |
| `src/converters/XmlConverter.js` | **Delete** |
| `src/converters/__tests__/JsonConverter.test.js` | **Delete** |
| `src/converters/index.js` | **Modify.** Remove 6 imports, remove 6 `registry.register()` calls. Only MarkItDownConverter + PlainTextConverter remain |
| `src/converters/MarkItDownConverter.js` | **Modify.** Enhance error handling — log which MarkItDownJS sub-package failed. No fallback chain needed |
| `src/converters/__tests__/Registry.test.js` | **Modify.** Simplify to 2-entry registry |
| `package.json` | **Modify.** Remove: `mammoth`, `pdfjs-dist`, `xlsx`, `papaparse` |
| `vite.config.js` | **Modify.** Remove manual chunks: `pdf`, `excel`, `docx`, `csv` |

**Pre-flight:** Test every format MarkItDownConverter claims to support before deleting fallbacks.

### 2.2 Replace Optimizer

| File | Action |
|------|--------|
| `src/utils/tokenizer.js` | **Modify.** Delete `optimizeMarkdown`, `optimizeCode`, `optimizeJson`, `optimizeXml`, `optimizeData`, `optimizeHtml` (~250 lines). Keep `normalizeText` as universal fallback |
| `src/utils/optimizer.js` | **Create.** Simplified optimizer: MarkItDown output → minimal cleanup (normalizeText). Raw JSON → TOON encode via `@toon-format/toon`. Everything else → normalizeText |

**Fallback:** If `@markitdownjs/optimizer` ships, use it. If not, the simplified optimizer handles all cases since MarkItDownJS already normalizes content to Markdown.

### 2.3 Replace Token Counting

**Decision point:** Evaluate `@markitdownjs/chunking` tokenizer API.

- If GPT-4 compatible → replace `gpt-tokenizer`
- If different tokenizer → keep `gpt-tokenizer` (users expect GPT counts)
- Consolidate dynamic import pattern either way

### 2.4 Migrate Chunking & Serialization

| File | Action |
|------|--------|
| `src/utils/tokenizer.js` | **Modify.** Simplify `createChunks` — everything is Markdown now, remove format branching. Evaluate `@markitdownjs/chunking` for heading-aware chunking |

**Fallback:** If MarkItDownJS chunking doesn't meet needs, keep custom chunker simplified for Markdown-only input.

**The .toon file format stays** — it's the product spec. Compression (fflate gzip) stays — independent of MarkItDownJS.

### Phase 2 Dependencies
- Remove: `mammoth`, `pdfjs-dist`, `xlsx`, `papaparse` (~1.5MB savings)
- Keep: `gpt-tokenizer`, `@toon-format/toon`, `fflate`

### Phase 2 Verification
- Test every MarkItDown-supported format: PDF, DOCX, PPTX, XLSX, HTML, CSV, XML, EPUB, TXT, MD, RTF
- Compare token counts before/after migration
- Run `npm run test` — updated tests pass
- Compare bundle size: should shrink significantly

## Phase 3: Feature Expansion (Weeks 11-16)

### 3.1 Model Selector
- **Create:** `src/components/ModelSelector.jsx`, `src/utils/models.js` (GPT-4o, Claude 3.5, Gemini 1.5 presets with cost/tokenizer config)
- **Modify:** `src/store/useSettingsStore.js`, `src/utils/tokenizer.js` (accept model param), `src/components/ResultsView.jsx` (cost estimate display)

### 3.2 Batch Processing
- **Create:** `src/components/BatchDropZone.jsx`, `src/components/BatchProgress.jsx`, `src/components/BatchResults.jsx`
- **Modify:** `src/store/useAppStore.js` (batch state), `src/App.jsx` (batch routing)
- Sequential processing with concurrency limit of 2-3. Max 20 files, 100MB total. Batch download as .zip via fflate.

### 3.3 Chunk Inspector
- **Create:** `src/components/ChunkInspector.jsx` (modal/slide-in panel with full chunk content, heading tree, token distribution, prev/next navigation, keyboard shortcuts)
- **Modify:** `src/components/ChunkPreview.jsx` (add "Open in Inspector" button)

### 3.4 Overlap Configuration
- **Modify:** `src/store/useSettingsStore.js`, `src/utils/tokenizer.js` (overlap param), UI for chunk overlap/size/split strategy

### 3.5 Shareable .toon Links
- **Create:** `src/utils/share.js` (URL-safe encoding of compressed .toon), `src/components/ShareModal.jsx`
- Encrypted client-side via Web Crypto API. URL hash contains decryption key. 7-day TTL. Fallback to download for large files.

- POST /convert endpoint: file upload → .toon output
- Rate limiting, file size validation

## Risk Register

| Risk | Mitigation |
|------|-----------|
| MarkItDownJS doesn't support a format that fallbacks handle | Test all formats before deleting; keep PlainTextConverter |
| `@markitdownjs/chunking` doesn't expose needed APIs | Keep custom chunker, simplified for Markdown-only |
| Zustand migration introduces regressions | Mirror existing state shape exactly; test all transitions |
| Chrome extension bundle too large | Tree-shake, lazy-load converters, on-demand loading |
